# M02 事后观察（不是判据）

M02 运行之后写的，不进入任何判据，不改 M01/M02 的输出。脚本 `scripts/m02_observation.py`，输出 `observation.json`。

## 1. 作者的"160 GHz"箭头指在哪里
- 用 M01 的定标与暗像素阈值（max(RGB)<140），在第 178–190 行、第 880–910 列定位箭头竖杆：中心第 897.4 列，对应 **164.3±0.5 GHz**。
- M02 T1 的首次确定下穿区间是 162.5–164.0 GHz。箭头位置比区间上端高 0.3 GHz，在箭头自身 ±0.5 GHz 的定位误差内。所以作者箭头标的正是这次下穿；对不上的是文字标签"160 GHz"。
- 摘要写的是"a 6.4-dB electrical bandwidth **over** 160 GHz"，与 163–164 GHz 相容；T1 检验的是正文 p.856 的"measured to be 160 GHz"。最自然的解释是标签向下取整，但这只是解释，没有被检验。
- 这次下穿掉进一个窄谷（166.3 GHz 处 S21 = −7.76±0.23 dB）。不计这个谷，S21 在 160.1 GHz 处是 −6.02±0.26 dB，仍在 −6.4 dB 以上。

## 2. T3 分频段
| 频段 (GHz) | 点数 | 高于 | 不定 | 低于 |
|---|---|---|---|---|
| (20, 50] | 126 | 0 | 126 | 0 |
| (50, 100] | 210 | 50 | 160 | 0 |
| (100, 170] | 290 | 290 | 0 | 0 |

**从 89.5 GHz 起，每个点都"高于"**；50 GHz 以下读数差在不确定度与 0.38 dB 失配余量之内。也就是说，"实测损耗高于仿真"在约 90 GHz 以上的读数精度内成立，在 50 GHz 以下读不出来。这条分段是看过结果后加的，不能把 T3 的"不定"改写成"成立"。
